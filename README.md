# Baseus Security — автономные снимки и Home Assistant

**Русский** | [English](README_EN.md)

Неофициальный экспериментальный клиент для получения свежих JPEG с совместимых
камер Baseus Security и их подключения к Home Assistant.

**Основной сценарий проекта — работа без телефона и планшета.** Во время съёмки
не нужны Android-приложение, ADB, USB-подключение, эмулятор или включённый экран.
Клиент сам обращается к облаку Baseus, пробуждает камеру, устанавливает P2P-соединение
и декодирует видеопоток в JPEG. Он не управляет приложением и не снимает его экран.

Камера должна быть предварительно настроена и привязана к вашему аккаунту Baseus.
Первичное добавление/привязку новой камеры проект пока не выполняет.

**Проверенная модель — Baseus Security S1.** Общее название интеграции не означает
подтверждённую поддержку остальных моделей: камеры с Tuya и другими протоколами
этим backend не поддерживаются.

Оба актуальных варианта работают напрямую, **без мобильного устройства**.
В Home Assistant устанавливается custom integration, а захват выполняет отдельный
Docker-контейнер. Это не Supervisor Add-on и не сервис постоянного live-видео.

## Возможности Home Assistant

- Последний кадр как сущность `camera`.
- Датчики батареи, времени последней успешной съёмки и облачной сессии.
- Вход в аккаунт Baseus через интерфейс HA, с отображением результата.
- Настройка интервала съёмки и хранения через «Устройства и службы».
- История последних **10–20 кадров на камеру** в медиабраузере HA.
- Внешний архив в подключённом каталоге/NAS со сроком хранения в днях.
- Кнопка «Снять все камеры», ограниченные повторы и защита от параллельных запусков.
- Русский/английский интерфейс и собственная иконка для HA 2026.3+.

По умолчанию: интервал **15 минут после завершения предыдущего цикла**, история
**20 кадров**, внешний архив **30 дней**, если подключён, и пропуск первых
**10 декодированных кадров**, чтобы дать штатной дате/времени камеры появиться.
Расписание и файлы хранит контейнер; открытая панель HA для съёмки не нужна.

## Как получается свежий снимок

1. Клиент получает актуальный список устройств из облака Baseus.
2. Отправляет MQTT `WatchDevice`, если включено пробуждение.
3. Устанавливает прямое XM/PPCS UDP-соединение с камерой и выполняет XM login.
4. Запрашивает видео, расшифровывает и декодирует H.264/HEVC.
5. Проверяет JPEG и атомарно сохраняет новый файл.

Новая съёмка никогда не подменяется кадром из кэша. При ошибке интеграция может
продолжать показывать предыдущий успешный снимок, но время `last_capture`
не обновляется и ошибка видна в атрибутах.

## Ограничения и безопасность

- Автономное получение свежего JPEG проверено на реальной S1. Другие модели,
  сети/NAT и полную установку HA/Docker/NAS нужно проверять отдельно.
- Пока реализован только прямой XM/PPCS UDP, без relay/TCP fallback. Не всякая
  сеть позволит установить соединение.
- Батарея — последнее показание, переданное камерой в облако, не отдельный live-замер.
- Новый login выполняется только по явной команде и **может завершить сессии
  приложения на других устройствах**. Автоматического повторного входа нет.
- Логин/пароль не сохраняются сервисом и интеграцией HA; сохраняется облачная
  сессия. Защищайте её, локальный API-ключ и резервные копии.
- Не открывайте порт API контейнера в Интернет. Используйте доверенную локальную
  сеть или HTTPS, особенно при передаче логина/пароля из HA.
- Личные конфиги, сессии, снимки, логи, PCAP, APK и сборки исключены из Git.
  Не добавляйте их принудительно. Общие константы SDK оставлены как часть протокола,
  а не как личные учётные данные.

## Проверки и сборка пакета

Для CLI нужен Python 3.11+; Docker-образ использует Python 3.13.

```sh
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -q
```

Тесты покрывают протокол, локальные UDP/HTTP-сеансы, хранение и логику форм.
HA flow-тесты используют тестовые doubles, а не настоящий интерфейс HA.
Локальные native/PCAP-материалы исследования в исходный пакет не входят.

```sh
python tools/build_ha_brand.py
python tools/build_ha_package.py
```

Пакет собирается по явному списку исходников, без секретов и записей камеры.
Существующий ZIP скрипт не перезаписывает.

## История разработки

На раннем этапе для исследования использовался Android/ADB-мост. Его код и
[архивные инструкции](LEGACY_ADB_RU.md) сохранены для истории и совместимости.
**Это не зависимость и не обязательный этап текущей установки.** Для новой
установки используйте автономный клиент или интеграцию Home Assistant выше.
