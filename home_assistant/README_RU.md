# Baseus Security для Home Assistant Container

**Русский** | [English](README_EN.md)

Версия **0.2.1**: контейнер захвата + custom integration; явный вход в Baseus
через HA, статус сессии и сохранение полей при ошибке формы.
Android/ADB не нужны. Самостоятельный клиент уже проверен с реальной S1;
**Полную проверку своего HA/Docker/NAS-окружения нужно выполнить перед эксплуатацией**.

## Возможности

- Настройка через «Устройства и службы»: интервал 60..86400 секунд,
  история 10..20 JPEG на каждую камеру, пропуск начальных кадров, срок архива.
- Последний снимок как `camera`, батарея и время успешной съёмки как `sensor`.
- Общее название Baseus Security и собственная жёлтая иконка камеры (HA 2026.3+).
- Кнопка «Снять все камеры»: асинхронный запуск без ожидания ответа камеры в HA.
- «Медиа → Baseus Security history»: просмотр короткой истории.
- Внешний архив в подключённом каталоге/NAS, по умолчанию 30 дней.
- Состояние, ключи, настройки и снимки переживают перезапуск контейнера.

Интервал общий для всех камер, отсчитывается **после завершения цикла**.
Одновременных циклов и очереди повторных нажатий нет. По умолчанию 15 минут,
20 кадров, пропуск 10 начальных кадров для появления штатного времени камеры.
Слишком частый опрос расходует батарею и мобильный трафик. Постоянного live-видео нет.

## 1. Подготовка сервера

Нужен Docker Compose на Linux (amd64/arm64), рядом с Home Assistant Container.
Распакуйте пакет в отдельную папку. В корне должны лежать `compose.yaml`,
`Dockerfile`, `baseus_service.py`, `baseus_autonomous.py` и `baseus_s1/`.
Все следующие команды выполняются из этой папки на сервере.

```sh
docker compose build
docker compose run --rm baseus python baseus_service.py init
```

Данные лежат в отдельном Docker volume `baseus_data`. Пользователь контейнера —
UID/GID 10001; файлы state и API-ключа не публикуются через HTTP.

## 2. Авторизация Baseus: через HA или перенос действующей сессии

Перенос файла больше не обязателен. Можно перейти к шагам 3–5, запустить сервис
и подключить интеграцию, затем «Настроить → Войти в Baseus» (подробности ниже).
Без действующей сессии сервис приостановит съёмку до явного входа. Если сессия
уже работает, заново входить не нужно. Перенос остаётся вариантом без нового login.

Новый login раньше сбрасывал другие сессии. Поэтому предпочтителен перенос
**своего** действующего `state/session.json` с ПК на сервер по защищённому каналу.
Не присылайте файл/токен в чат. Если companion уже работает, перед заменой сессии
остановите его командой `docker compose stop baseus`. После создания контейнера:

```sh
docker compose create
docker compose run --rm -T baseus python -c 'from pathlib import Path; Path("/data/state").mkdir(exist_ok=True)'
docker compose cp ./session.json baseus:/data/state/session.json
docker compose run --rm -T --user root baseus chown 10001:10001 /data/state/session.json
docker compose run --rm -T baseus chmod 600 /data/state/session.json
```

Выполняйте команды по одной, дожидаясь приглашения терминала. Для неинтерактивных
команд `-T` исключает захват вставленных следующих команд временным контейнером.

`./session.json` здесь — доставленная на сервер копия. Защитите и её от чтения.
Для нового региона измените `BASEUS_COUNTRY` в Compose; он должен совпадать
с регионом сохранённой сессии.

Если действующей сессии нет, выполните **явный интерактивный** вход:

```sh
docker compose run --rm baseus python baseus_autonomous.py login --state /data/state --log-file /data/login.log
```

Введите email/пароль в терминале. Пароль не передавайте аргументом команды.
**Этот вход может завершить сессии других устройств.** Автоматического login
или повторного входа в контейнере/интеграции нет. При `auth_required` расписание
приостанавливается: выполните явный вход из HA либо обновите файл сессии и
перезапустите контейнер. Остановка контейнера для входа через HA не нужна.

## 3. Сеть между HA и контейнером

По умолчанию API опубликован только на `127.0.0.1:8099` Docker-хоста.

- Если HA использует `network_mode: host` на том же Linux-хосте,
  адрес интеграции: `http://127.0.0.1:8099`.
- Если HA работает в bridge-сети, **его localhost — не Docker-хост**.
  Подключите оба контейнера к одной пользовательской Docker-сети и используйте
  `http://baseus:8099`, либо настройте доступ к порту через доверенный LAN-адрес.
- Если HA на другом сервере, замените публикацию порта в Compose на
  `"LAN_IP_СЕРВЕРА:8099:8099"` и разрешите доступ только HA на firewall.

Не публикуйте порт 8099 в Интернет. Ключ передаётся в заголовке Authorization;
на недоверенной сети нужен HTTPS reverse proxy. Редиректы API не выполняются,
проверка TLS не отключается. Сетевые параметры `--bind-address`/Windows
`--interface-index` в Linux-контейнер не переносятся.

## 4. Подключение внешнего архива

NAS сначала подключается **на Docker-хосте** обычным SMB/NFS/mount; сервис
не хранит и не настраивает NAS-пароли. В `compose.yaml` раскомментируйте bind mount
и `BASEUS_ARCHIVE`. Каталог должен быть доступен UID 10001 для записи.

```yaml
volumes:
  - baseus_data:/data
  - type: bind
    source: /mnt/nas/cameras
    target: /archive
    bind:
      create_host_path: false
environment:
  BASEUS_DATA: /data
  BASEUS_COUNTRY: RU
  BASEUS_ARCHIVE: /archive/baseus_s1
```

Это фрагмент **внутри сервиса `baseus`**, а не замена всего Compose-файла.
Выделите отдельный каталог `baseus_s1`. Короткая история остаётся в `/data`,
архив — `/archive/baseus_s1/<camera_id>/*.jpg`. По сроку удаляются только файлы
строгого формата, созданного клиентом, в каталогах камер этого сервиса.
Посторонние файлы не удаляются. Уменьшение лимитов включает удаление старых снимков.
Архив не бесконечный: срок 1..3650 дней настраивается в HA, по умолчанию 30.
При недоступном NAS последний кадр и короткая история сохраняются; выставляется
`archive_error`. Пропущенные копии на NAS автоматически не дозагружаются.
Проверяйте, что NAS действительно смонтирован: существующий пустой mountpoint
не является доказательством доступности NAS. Не используйте каталог архива для
чужих файлов с совпадающими именами.

## 5. Запуск и установка интеграции

```sh
docker compose up -d
docker compose logs --tail 50 baseus
```

Контейнер начинает съёмку после запуска, затем работает по расписанию независимо
от открытой панели HA. Настройки API/HA сохраняются в volume.

Скопируйте `custom_components/baseus_s1` из пакета в:

```text
<каталог конфигурации HA>/custom_components/baseus_s1/
```

В контейнере HA это `/config/custom_components/baseus_s1/`. Перезапустите HA.
Затем «Настройки → Устройства и службы → Добавить интеграцию → Baseus Security».

Введите URL контейнера и **локальный API-ключ**. Посмотреть ключ в своём терминале:

```sh
docker compose exec baseus cat /data/api_token
```

Не публикуйте вывод и не используйте вместо него облачный токен Baseus.
Ключ хранится в конфигурации HA: защищайте резервные копии HA и Docker volume.
Пароль Baseus не записывается в config entry или options. При явном входе он
передаётся контейнеру только для одной операции. Смена адреса/API-ключа в этой версии —
удалить запись интеграции и добавить заново; снимки в companion не удаляются.

Камеры появятся после первого завершённого цикла. Данные API HA перечитывает
каждые 15 секунд — это **не** новые пробуждения камеры. Просмотр последнего кадра
тоже не инициирует съёмку. «Настроить → Съёмка и хранение» меняет интервал и хранение.

### Вход из интерфейса HA и обратная связь

«Настройки → Устройства и службы → Baseus Security → Настроить» теперь
открывает меню:

- **Съёмка и хранение** — прежние параметры, введённые значения остаются при ошибке сохранения.
- **Войти в Baseus** — email, пароль и обязательное подтверждение риска завершения
  сессий других устройств. Только отправка этой формы вызывает новый login.
- **Статус облачной сессии** — нет сессии / пока не проверена / принята при последней
  проверке / отклонена. Наличие файла токена не выдаётся за успешную авторизацию.

Форма подключения также сохраняет введённые адрес и API-ключ при ошибке.
После принятия команды входа показывается ожидание, затем успех, отказ, ошибка
или неподтверждённый результат. Контейнер выполняет вход в фоне, HA только
опрашивает результат: потеря соединения не вызывает повторную отправку пароля.
При неподтверждённом результате сначала проверьте датчик сессии, не повторяйте
вход вслепую. На время съёмки или другого входа новая команда отклоняется как busy.
После успеха облачная сессия сохраняется и съёмка возобновляется без перезапуска.

Отдельный датчик **«Облачная сессия»** появляется даже до обнаружения камер.
Его атрибуты показывают наличие сессии, ход/результат и время последнего входа,
безопасный код ошибки. После рестарта наличие токена имеет состояние «не проверена»
до первого облачного запроса; предыдущий результат входа хранится отдельно.

Логин и пароль **не хранятся** в контейнере или настройках HA: `credentials_stored`
всегда false. Пароль находится в памяти формы до отправки/закрытия и во время
операции на сервере, затем не сохраняется; остаётся только облачный токен.
После отклонённого входа пароль потребуется ввести заново. Автоматического
повторного login нет. Регион задаётся `BASEUS_COUNTRY` контейнера, например RU.
Используйте доверенную локальную сеть или HTTPS между HA и сервисом — API-ключ
не шифрует пароль при передаче по обычному HTTP.

### Обновление с 0.1.x до 0.2.x

Обновите исходники контейнера, включая `baseus_s1/`, сохранив свой Compose с
настроенной сетью/NAS. Пересоберите и запустите:

```sh
docker compose build baseus
docker compose up -d baseus
```

Замените **весь** каталог `/config/custom_components/baseus_s1/` в HA новыми
файлами пакета и перезапустите HA. Действующую запись интеграции/volume не удаляйте:
существующие параметры и сессия продолжают работать. Новый вход автоматически
не запускается. Только замены файлов контейнера недостаточно для нового UI.

### Название и иконка в 0.2.1

В интерфейсе используется Baseus Security, без привязки к модели S1. По-прежнему
проверена только S1; другие модели могут использовать несовместимые протоколы.
Внутренний domain/каталог `baseus_s1` и unique IDs сохранены для совместимости.
**Не переименовывайте каталог интеграции** и не удаляйте её запись. Старый
стандартный заголовок записи меняется автоматически; пользовательский заголовок
не перезаписывается. Имена самих камер из облака остаются прежними.

Иконки `brand/icon.png` и `brand/icon@2x.png` входят в пакет. Это оригинальная
пиктограмма камеры, не официальный логотип Baseus/HA. Локальные изображения
интеграций поддерживаются с **Home Assistant 2026.3**. На более старом HA может
оставаться стандартная заглушка. При обновлении копируйте также `brand/` и все
JSON-переводы, перезапустите HA и обновите страницу Ctrl+F5, чтобы не видеть кэш.
Для одного лишь изменения названия/иконки контейнер Baseus пересобирать не нужно.

## 6. Панель и история

Пример карточки: `home_assistant/dashboard.example.yaml`. Замените entity IDs
на реальные из списка сущностей HA. Встроенная picture-entity показывает
последний кадр, рядом — заряд, время и кнопка съёмки. История открывается через
«Медиа → Baseus Security history → камера». Это встроенный медиабраузер, не отдельная
кастомная frontend-карточка. Внешний архив просматривается средствами NAS.
Подпись файла в истории — UTC-время начала успешной попытки; датчик последней
съёмки показывает время получения JPEG. Ни одно из них не выдаётся за часы сенсора.

Кадры не выкладываются в `/config/www`/`/local`. История идёт через авторизацию
HA и короткоживущие подписанные URL (5 минут). Не передавайте такие ссылки другим.

Если новый снимок не получен, прошлый остаётся, но `last_capture` **не обновляется**.
Причина видна в атрибутах камеры (`status`, `error_code`, `archive_error`).
Батарея имеет источник `cloud_device_info`: последнее облачное показание, не
отдельный свежий live-замер. Настоящее время OSD приходит от камеры; не рисуется ПК.

## Проверка установки

1. Один цикл создаёт JPEG, датчик показывает время; следующий обновляет его.
2. Настройте лимит 10, выполните >10 циклов: в медиабраузере остаётся 10 кадров.
3. Два нажатия подряд не создают параллельную съёмку.
4. Перезапустите companion: предыдущий JPEG/настройки/история остаются.
5. Перезапустите HA: сущности не дублируются, истории доступны только с авторизацией.
6. Проверьте NAS-копию и `archive_error`, не удаляя рабочие пользовательские данные.

Локальные тесты без камеры: `python -m unittest discover -s tests -q`
после установки `requirements-test.txt`. Flow-тесты используют небольшие doubles
HA и не заменяют проверку его настоящего интерфейса. Реальные HA/Docker/NAS smoke-тесты
нужно выполнить на сервере; не считать офлайн-тесты доказательством установки.

## Логи и обновление до 0.1.1

```sh
docker compose logs -f --tail 100 baseus
```

По умолчанию `BASEUS_LOG_LEVEL=INFO`. В журнале видны:

- запуск сервиса с действующими интервалом и лимитами хранения;
- первый запрос с корректным API-ключом, затем после 120 секунд без запросов;
  это подтверждение авторизации API-клиента, не доказательство, что клиент именно HA;
- запрос применения настроек и изменённые числовые значения; неизменённые
  настройки отмечаются отдельно;
- запуск по расписанию или кнопке, отказ повторному нажатию при активной съёмке;
- этапы штатного клиента: список камер, попытка, MQTT wake, P2P, XM login,
  первый видеокадр, декодирование и сохранение JPEG;
- запись истории/архива, итоговые количества успешных/ошибочных снимков и
  UTC-время следующего запуска;
- `auth_required` с явной приостановкой расписания, без автоматического login.

Опрос `/status` каждые 15 секунд и чтение JPEG не засоряют INFO. Отказы API-ключа
ограничены одним предупреждением в минуту. В Compose можно временно добавить:

```yaml
environment:
  BASEUS_LOG_LEVEL: DEBUG
```

DEBUG включает только наши числовые/типовые метаданные: операции API, каналы,
размеры пакетов и sequence. Полные URL, query, заголовки, тела запросов/ответов,
API-ключ, облачные/P2P/MQTT-секреты и произвольные сообщения исключений не
пишутся. Сырые access logs HTTP по-прежнему отключены. Docker ведёт сбор stdout/
stderr; отдельного файла журнала сервиса внутри volume нет.

Для обновления перенесите новые исходники `baseus_s1/` и `baseus_service.py`,
сохранив свой `compose.yaml` с рабочим IP/сетью и NAS-mount. Затем:

```sh
docker compose build baseus
docker compose up -d baseus
```

Обычный `restart` не подхватит исходники, встроенные в старый образ. Docker volume
с сессией/ключом/кадрами нужно сохранить; **не выполняйте `down -v`**. Менять
интеграцию HA только ради этих логов не обязательно: HTTP-контракт не изменился.

## Почему отдельный контейнер

HA Container не поддерживает Supervisor Add-ons. Нативный PyAV и долгие
PPCS-попытки вынесены из HA, чтобы не блокировать его event loop и не конфликтовать
с версиями его библиотек. Альтернатива — запуск всего клиента внутри integration —
проще по числу контейнеров, но существенно хуже по изоляции и обновлению.
Цена решения: два устанавливаемых компонента и локальный защищённый API.
Контракт и границы хранения: [CONTRACT.md](CONTRACT.md).
