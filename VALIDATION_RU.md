# Проверка на физической Baseus S1 — 18.09.2026

> Ниже — дневная проверка Android-съёмки. Вечером того же дня отдельно подтверждены
> прямые HTTP API и MQTT WatchDevice: [CLOUD_VALIDATION_RU.md](CLOUD_VALIDATION_RU.md).

## Окружение

- Компьютер: Windows, Python 3.11.
- Планшет: Samsung SM-T865, Android 12, USB ADB, без root.
- Baseus Security на планшете: **1.5.0**.
- Камера: **S1 / S0SW00**, имя «Задний двор».
- Прошивка, показанная в приложении: `1.01.17_1.13.47_1.4.4_1.04.06`.
- Backend: `android-live-capture`, пробуждение через авторизованное приложение.

Серийные номера записаны в локальный `config.json`. Параметры камеры не менялись.
Планшет и компьютер остаются необходимыми для этого режима получения изображения.

## Найденные особенности и исправления

1. Установлена 1.5.0, а исходный XAPK был 1.11.0. APK 1.5.0 получен с планшета
   и отдельно исследован. В нём `LiveFragment` также вызывает
   `getCurrentMainScreenshot()`, а `AppFileUtil.g()` сохраняет JPEG в
   `Pictures/xm_baseusipc`. Оснований заменять live capture превью нет.
2. Обычный `uiautomator dump` на экране live view выдаёт
   `ERROR: could not get idle state`. Добавлен backend UIAutomator2 с
   `waitForIdleTimeout=0` и `waitForSelectorTimeout=0`.
3. UI-селекторы подобраны по реальному интерфейсу:
   - открыть единственную камеру: `com.baseus.security.ipc:id/iv_thumbnail`;
   - сделать снимок: точный текст `Захват`, только когда элемент активен.
4. При нескольких камерах селектор превью станет неоднозначным и скрипт
   остановится, а не выберет произвольную камеру. Тогда потребуется уточнить UI-путь.

## Реальные запуски

Время в таблице — локальное время планшета/компьютера (UTC+5).
В именах файлов и JSON используется UTC.

| Попытка | Старт | Результат |
|---|---|---|
| Первая | 16:20:02 | Таймаут ожидания активного элемента снимка; старый JPEG не принят, приложение закрыто |
| Автоматический повтор | 16:21:53 | Новый JPEG сохранён в 16:22:11, время в самом изображении **16:22:08** |
| Отдельный запуск после паузы | 16:23:49 | Новый JPEG сохранён в 16:24:07 с первой попытки, время в изображении **16:24:03** |

Файлы:

- `captures/s1_20260918T112153_f51cc984.jpg` — 2304×1296, 2 507 922 байта;
- `captures/s1_20260918T112349_5ba0419e.jpg` — 2304×1296, 2 504 993 байта.

Оба JPEG открыты и просмотрены. Это кадры камеры без интерфейса планшета.
Изображения содержат разные текущие временные отметки, соответствующие новым
live-сессиям. После каждого завершённого запуска Baseus принудительно остановлен.
Это проверка свежести по видимой временной отметке камеры; протокольный timestamp
сенсора скрипт не извлекает, поэтому `sensor_timestamp_verified` в JSON остаётся false.

Успешная попытка занимает примерно 18 секунд вместе с запуском и закрытием
приложения. Причина первого таймаута точно не установлена; ограниченный повтор
отработал корректно. Долговременная стабильность почасового режима ещё не измерена.

## Автоматические проверки

`python -m unittest discover -s tests -v`: **22 теста, OK**.
Добавлены проверки ошибки ADB dump, отключения idle wait, повторного использования
UIAutomator2 и сброса соединения при ошибке.

## Что этим запуском не проверено

- Прямая авторизация Python-клиента в облаке и прямое MQTT-пробуждение.
  Для этих запусков использовалась уже авторизованная сессия Android-приложения.
- Самостоятельный приём XM/PPCS-видео без планшета.
- Работа на Linux и длительная работа по часовому расписанию.
- Физическое состояние сна камеры перед запуском не измерялось отдельно;
  проверено открытие новой live-сессии после остановки предыдущей.

Готовая команда для разового повторения:

```powershell
.\.venv\Scripts\python.exe baseus_capture.py once
```

Для почасового режима:

```powershell
.\.venv\Scripts\python.exe baseus_capture.py run
```
