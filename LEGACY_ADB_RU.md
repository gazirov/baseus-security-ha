# Архив: прежний Android/ADB backend

**Это описание раннего прототипа, а не текущий способ работы проекта.**
Планшет нужен только этому старому backend. Для автономного клиента и интеграции
Home Assistant телефон, планшет, ADB и USB-подключение не требуются.
Текущая документация: [Русский](README.md) | [English](README_EN.md).

Ниже сохранены исторические инструкции и результаты локальной отладки. Упоминания
уже созданного окружения, заполненного config.json и конкретного планшета относятся
к той отладке, а не к установке пользователя. Этот путь не рекомендуется для новой
установки; он оставлен для истории исследования и совместимости.

Python 3.11+, Windows/Linux. Точка входа: `baseus_capture.py`.

## Что реализовано и что ещё требует проверки

Этот backend использует Android-мост для видео. Планшет без root должен быть
подключён к компьютеру во время съёмки. Автономный XM/PPCS backend теперь
реализован отдельно, см. ссылки выше.

| Возможность | Реализация |
|---|---|
| Авторизация непосредственно из Python | Региональные серверы, RSA-пароль, подпись тела, локальная сессия |
| Получение устройств | XM RPC `GetUserDeviceList` / `GetUserDevice` |
| Пробуждение непосредственно из Python | MQTT TLS, `WatchDevice`, ожидание ответа с совпадающим `seq` |
| Свежий кадр | Штатный live capture Baseus на планшете через ADB, JPEG переносится на компьютер |
| Раз в час | Последовательный цикл каждые 3600 секунд, без «догоняющих» запусков |
| Ошибки | Таймауты, до двух попыток за цикл, закрытие Android-сессии в `finally` |
| Журнал | Консоль и ротация `logs/baseus.log`, без паролей/токенов/тел API |

Облачный протокол восстановлен по APK 1.11.0. **Прямая авторизация, получение
устройств и MQTT WatchDevice проверены** на реальном аккаунте 18.09.2026:
[CLOUD_VALIDATION_RU.md](CLOUD_VALIDATION_RU.md). Android-съёмка проверена 18.09.2026
на физической S1 через Samsung SM-T865 (Android 12, Baseus Security 1.5.0):
получен JPEG 2304×1296 с текущим временем в изображении, сессия закрыта.
Подробности двух успешных съёмок и одного таймаута: [VALIDATION_RU.md](VALIDATION_RU.md).
APK установленной 1.5.0 отдельно проверен: кнопка снимка также сохраняет bitmap
из `getCurrentMainScreenshot()`, а не HTTP-превью.
Статус автономного XM/PPCS-исследования: [P2P_RESEARCH_RU.md](P2P_RESEARCH_RU.md).
UI-селекторы нужно один раз подобрать на вашем планшете. Их нет в конфигурации
по умолчанию: неправильную кнопку скрипт угадывать не будет.
Локальный `config.json` уже настроен для подключённого планшета и камеры «Задний двор».

## Как обеспечивается новый кадр

1. Останавливается процесс Baseus: видеодекодер предыдущей сессии уничтожается.
2. Приложение запускается заново, открывается live view выбранной камеры.
3. После ожидания потока нажимается **кнопка фото именно в live view**.
4. Принимается только новый/изменившийся JPEG с именем `SN + цифры + .jpg`
   в каталоге штатных снимков, созданный после запроса.
5. JPEG полностью декодируется для проверки, сохраняется атомарно.
6. Baseus закрывается, даже если произошла ошибка или Ctrl+C.

В APK `LiveFragment.c0()` вызывает `getCurrentMainScreenshot()`, а SDK получает
bitmap из видеодекодера (`XmMovieViewController → m0 → decoder`). HTTP-превью
и скриншот экрана планшета не используются как результат съёмки.

Это проверка происхождения кадра из **новой live-сессии**, а не проверка
аппаратного времени экспозиции: скрипт не получает timestamp сенсора.
`requested_at_utc` и `received_at_utc` в JSON — время запроса и получения,
не заявленное время съёмки сенсором. После настройки обязательно проведите
описанную ниже проверку с изменением сцены и с недоступной камерой.

## 1. Установка

Из каталога проекта:

### Windows / PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe baseus_capture.py init
```

В текущей рабочей папке `.venv` уже создана и зависимости установлены.

### Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python baseus_capture.py init
```

Далее `python` в примерах означает Python из `.venv`.

Установите [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools).
Либо запустите `python setup_adb.py`: он скачает официальный архив Google в `tools/`
и запишет путь к ADB в существующий `config.json`, сохранив остальные настройки.
На Debian/Ubuntu обычно достаточно `sudo apt install adb`.
Если `adb` не в PATH, укажите полный путь в `config.json` → `android.adb`.
Для Windows в JSON обратный слэш удваивается: `C:\\Android\\platform-tools\\adb.exe`.

## 2. Подключение планшета

1. Включите режим разработчика и «Отладка по USB».
2. Подключите USB, подтвердите разрешение отладки на планшете.
3. Проверьте `adb devices`: статус должен быть `device`, не `unauthorized`.
4. При нескольких устройствах запишите нужный ID в `android.serial`.
5. Откройте Baseus Security и войдите в аккаунт **на планшете**.
6. Проверьте, что S1 показывает живое видео и штатная кнопка фото сохраняет JPEG.
7. Для автоматической работы планшет должен иметь сеть, питание и доступный UI.
   Скрипт будит экран и пробует закрыть обычный keyguard, но PIN/пароль не вводит.

Вход в Python и вход в Android-приложение — **две отдельные сессии**.
Токен Python не внедряется в приложение. На первом этапе удобнее получать кадры
через уже авторизованное приложение; прямой cloud-клиент проверять отдельно.

При `wake_before_capture: false` пробуждение и авторизация камеры выполняются
самим Baseus при открытии live view. Это полноценная новая видеосессия, а не превью.

```bash
python baseus_capture.py doctor
```

`doctor` проверяет ADB, версию приложения, доступность UI dump и каталог снимков.
Он не подтверждает работоспособность камеры.

Для live view используется `android.ui_backend: "uiautomator2"`: библиотека
запускает служебный UIAutomator-сервер через ADB, без root и изменения Baseus.
Ожидание неподвижного интерфейса отключено — обычный `uiautomator dump` на этом
планшете выдавал `could not get idle state` во время видео. Backend `adb` оставлен
как вариант для устройств, где стандартный dump работает.

## 3. Настройка UI и серийного номера

В `config.json` заполните `camera.sn` из настроек камеры. Это серийный номер,
не имя «S1» и не код модели `S0SW00`.

### Интерактивная настройка

```bash
python baseus_capture.py configure-ui
```

Мастер перезапустит Baseus, покажет элементы текущего экрана списком и предложит
выбрать камеру, при необходимости промежуточные кнопки, затем кнопку фото.
Он спросит серийный номер и сохранит селекторы в `config.json`.
Скрипт сам нажимает выбранные элементы навигации; не выполняйте эти переходы
вручную, иначе сохранённая последовательность будет неполной. Кнопка фото в
мастере не нажимается — её работу проверяет отдельный `once`.

Если мастер не показывает нужный элемент, ниже описана ручная настройка.

### Элемент открытия камеры

Оставьте на планшете главный экран Baseus со списком камер:

```bash
python baseus_capture.py inspect --label home
```

Создаются `diagnostics/home.xml` и `diagnostics/home.png`; в консоли — элементы
интерфейса. Найдите уникальный текст имени камеры или `resource-id` её кнопки.
Запишите последовательность нажатий, ведущую от главного экрана к live view:

```json
"open_live": [
  {"text": "Название вашей камеры"}
]
```

Если нужны два нажатия, добавьте два объекта в массив в нужном порядке.
Селекторы сопоставляются точно, без поиска подстроки.

### Элемент штатного снимка

Вручную откройте живое видео S1:

```bash
python baseus_capture.py inspect --label live
```

В `diagnostics/live.xml` найдите элемент **фото/снимка**. Запишите, например:

```json
"capture_selector": {"text": "Фактическая подпись кнопки в вашем UI"}
```

Другие формы селектора:

```json
{"resource_id": "com.baseus.security.ipc:id/ФАКТИЧЕСКИЙ_ID"}
{"description": "Фактический content-desc"}
{"resource_id": "com.baseus.security.ipc:id/ФАКТИЧЕСКИЙ_ID", "text": "Фактический текст"}
```

Примеры выше — **формат, не готовые идентификаторы кнопок**. Используйте значения
из своего XML. При нескольких совпадениях скрипт останавливается с ошибкой.
Если нужная кнопка не представлена в UI XML, текущий backend потребует адаптации;
координатного нажатия наугад в нём нет.

Скрипт проверяет пакет `com.baseus.security.ipc`; шаблон ожидает версию `1.11.0`,
а локальная проверенная конфигурация — `1.5.0`.
При другой версии сначала нужно проверить путь получения фото и селекторы,
затем при необходимости изменить `expected_app_version`.

Для Android 10+ ожидается каталог `/sdcard/Pictures/xm_baseusipc`.
Для Android 8–9 из кода следует каталог `/sdcard/Pictures/xm_baseusipc/PictureOpen`;
если ваш планшет старый, укажите его в `image_directory`.

## 4. Первый снимок и проверка свежести

```bash
python baseus_capture.py once
```

Результат: `captures/s1_<UTC>_<id>.jpg` и JSON с метаданными.
Снимки остаются и в галерее планшета; автоматического удаления нет.

До включения расписания:

1. Получите первый кадр.
2. Измените сцену перед камерой — например, поставьте лист с текущим временем.
3. Выполните `once` ещё раз и убедитесь, что JPEG показывает новую сцену.
4. При недоступной камере повторите `once`: он должен завершиться ошибкой,
   без подстановки старого кадра.

При медленном пробуждении увеличьте `capture_timeout` и `stream_wait_seconds`.
Внутри одной live-сессии кнопка фото нажимается не более трёх раз, если JPEG
не появился. Повтор целой сессии ограничен `attempts_per_cycle`.

## 5. Прямая авторизация и MQTT из Python

Этот путь экспериментальный и независим от настройки UI.
Укажите `cloud.country` — страну, выбранную **при регистрации аккаунта**.
Адрес региона берётся из публичного `area.json` Baseus.

```bash
python baseus_capture.py login
python baseus_capture.py devices
```

`login` спросит email и пароль; пароль вводится без отображения.
Сессия сохраняется в `state/session.json`, пароль не сохраняется.
`devices` выводит структуру ответа без ключей пробуждения/P2P-паролей и сохраняет
`state/devices.redacted.json`. Серийные номера остаются в этом файле.

Из данных устройства заполните `camera.product_id` — **не** `S0SW00`.
В локальном config.json этот параметр уже заполнен. Подробные данные выбранной
камеры можно получить командой `python baseus_capture.py device`; очищенный ответ
сохраняется в `state/device.redacted.json`.

```bash
python baseus_capture.py wake
```

Скрипт получает данные выбранного устройства, его `wake_key`, MQTT-реквизиты,
подписывается, посылает `WatchDevice` и ждёт коррелированного ответа.
Подтверждение публикации брокером не считается успешным пробуждением.
Если фактическая схема ответа отличается от исследованной, команда завершится
ошибкой; пригодится обезличенный `devices.redacted.json` для корректировки.

После проверки можно поставить `cloud.wake_before_capture: true`: `once/run`
будут делать прямое MQTT-пробуждение перед открытием Baseus на планшете.
Приложение при открытии live view также может послать свою команду пробуждения.
При конфликте двух сессий оставьте `false` и используйте пробуждение приложением.

Для автоматического обновления истёкшей Python-сессии задайте переменные окружения
`BASEUS_ACCOUNT` и `BASEUS_PASSWORD` для процесса. Если их нет, требуется повторный
ручной `login`. За одну операцию выполняется не более одного обновления сессии.

`login_base_url` и `xm_url` — необязательные переопределения для исследования
реального регионального маршрута. Обычно оставляйте пустыми; пути RPC не угадываются,
XM host получается подписанным discovery-запросом. TLS проверяется; при необходимости
доверенный MQTT CA можно указать через `mqtt_ca_file`. Отключения проверки TLS нет.

## 6. Раз в час

```bash
python baseus_capture.py run
```

Первый снимок запрашивается сразу, затем каждые `interval_seconds` (3600 по умолчанию).
После сна компьютера пропущенные интервалы не «догоняются» серией пробуждений.
Ctrl+C завершает цикл; активная Android-сессия закрывается.

Альтернатива на Linux — запускать `once` через cron раз в час:

```cron
0 * * * * /absolute/project/.venv/bin/python /absolute/project/baseus_capture.py once --config /absolute/project/config.json
```

На Windows можно аналогично создать задачу в Task Scheduler с полным путём к
`.venv\Scripts\python.exe` и аргументами `baseus_capture.py once --config ...`.
Используйте тот же пользовательский профиль, который авторизовал ADB-подключение.
Для одного `state_directory` допускается только один экземпляр программы.

Все относительные пути результатов считаются от каталога `config.json`.
Путь к `adb` лучше задавать абсолютным при запуске планировщиком.

## Проверки и диагностика

```bash
python -m unittest discover -s tests -v
python baseus_capture.py doctor
python baseus_capture.py once --verbose
```

Тесты выполняются без камеры и сети: RSA, подписи с независимыми тест-векторами,
логика login, MQTT request/reply, отбрасывание старых/повреждённых файлов,
закрытие сессий, межпроцессная блокировка и пропуск просроченных интервалов.
Они выполнены на Windows; Linux-код блокировки требует проверки на Linux.

Для следующего этапа нужны результаты `doctor` и UI XML домашнего/live экрана.
`diagnostics/*.png` показывают экран с личными данными/изображением камеры.
Не отправляйте `session.json`, пароли или необезличенные сетевые дампы.

Источники восстановленного протокола: [RESEARCH_RU.md](RESEARCH_RU.md).
